# 墨锭重复试验结论台

在原有试磨室基础上扩展为重复试验结论台：试磨登记 → 满 3 条有效记录结题 → 复核生效 → 修正留痕。

运行：

```bash
npm start
```

访问 `http://localhost:3037`。数据保存在 `data/ink-stick-testing.json`（先写临时文件再改名，不落半条数据）。

## 规则

- **试磨登记**：操作人、纸样、水量、温湿度、评分，按墨锭归入试炼组。
- **有效判定**：温度 15–30℃、湿度 40–75%RH 之外为环境超差；与组内已有记录完全相同为重复记录。失效记录不计入结论并提示补测。
- **结题**：每组至少 3 条有效记录方可提交结题复核。
- **复核**：复核人不得参与本组试磨，也不得与提交人/修改人相同；通过即生效，驳回须写明原因并退回补测。
- **修正**：生效结论只能通过修正变更。修正复核期间查询仍返回旧版；通过后整体切换为新版本，旧值、修改人、时间、原因全部留痕。
- **并发**：登记按 clientToken 幂等，并发补测/重复复核只成功一次；失败请求不写库。

## 主要接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| GET/POST | `/api/groups` | 试炼组列表 / 建组 |
| GET | `/api/groups/:id` | 组详情（有效数、异常原因、版本、差异、日志） |
| POST | `/api/groups/:id/records` | 试磨登记（携带 clientToken 幂等） |
| POST | `/api/groups/:id/conclusion` | 提交结题复核 |
| POST | `/api/groups/:id/review` | 复核结题（approve/reject） |
| POST | `/api/groups/:id/amendments` | 发起修正 |
| POST | `/api/groups/:id/amendments/review` | 复核修正 |

## 验证

```bash
node verify.mjs            # API 层：成功/并发/越权/回滚/重启，42 项断言
node verify-migration.mjs  # 旧版数据迁移：旧结论按生效时间重建补测边界，11 项断言
node browser-test.mjs      # 浏览器层：桌面+手机视口走通登记/结题/复核/修正，17 项断言（需 playwright-core）
```

API 验证覆盖：成功流程、并发补测幂等、重复复核冲突、越权修正/复核拦截、失败回滚（库文件字节不变）、驳回补测、修正整体切换、需补测提示随生效结束/随新增失效重现、重启后数据完好。迁移验证覆盖：旧版结论（无 recordCount）按生效时间重建判断边界，生效前失效记录不触发提示、升级后新增失效记录触发、旧结论与历史不被改写、重启后判断一致。
